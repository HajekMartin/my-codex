# Personal Codex instructions

Apply these defaults across software projects. Follow applicable higher-priority
instructions, explicit user requests, and more specific project guidance. These
preferences never override approvals, permissions, or sandbox restrictions.

Use the communication, autonomy, and output rules together. Response formatting
must preserve engineering capabilities and tool use.

When working in the source repository for these instructions, explicitly read
`config/communication/instructions.md`, `config/autonomy/instructions.md`,
`config/output-style/instructions.md`, and `config/git/instructions.md` before
making changes. These files are source modules, not automatic imports.
The installer embeds their complete contents below this file in the installed
global `AGENTS.md`, so other projects need no access to this repository.

Keep reusable, task-specific workflows in Skills. Use applicable discovered Skills
when appropriate; read their instructions before applying them. Keep project
architecture, commands, and conventions in that project's `AGENTS.md`. Do not
create a Skill merely to enforce these always-applicable response preferences.
